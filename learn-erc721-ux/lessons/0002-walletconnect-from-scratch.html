TD ERC721 UX 101 · Leçon 0002 · ~10 min

WalletConnect sans librairie de connecteur

Le même provider EIP-1193, mais le wallet est sur ton téléphone.

Objectif : connecter ton wallet mobile en scannant le QR de ta page, et expliquer au prof les trois étapes de connectWalletConnect(). Ça couvre le point 2 de « Wallet Integration ».

0. Échauffement : rappel de la leçon 0001

Quelle méthode ouvre la demande de connexion dans le wallet ?
eth_requestAccounts. eth_accounts ne fait que lire une connexion existante, sans popup. Voir 0001.
Que garantit la spec quand wallet_switchEthereumChain réussit ?
Seulement le retour null (EIP-3326). La popup est un should : tu l'as vu avec Rabby, qui change de réseau sans demander.

1. Le problème

Sur un ordinateur sans extension, window.ethereum n'existe pas. Le wallet (et donc les clés) est sur le téléphone. Il faut un canal entre la page et le téléphone : c'est WalletConnect.

2. Trois idées

idéece que c'est
URI de pairingune chaîne wc:… qui contient de quoi chiffrer la conversation. Le QR code n'est que cette chaîne dessinée.
Relayun serveur de WalletConnect qui fait transiter les messages chiffrés entre la page et le téléphone. Ton Project ID identifie ton app auprès de lui.
Sessionce que le téléphone accepte : quels comptes, quelles chaînes (optionalChains: [11155111]), quelles méthodes.

Le point clé : @walletconnect/ethereum-provider est « EIP-1193 compliant »[Reown]. Il a donc le même request() et les mêmes accountsChanged / chainChanged que window.ethereum. Ton switchToSepolia et ton submitExercise marchent sans changement : ils demandent juste getProvider().

3. Pourquoi on dessine le QR nous-mêmes

La doc indique que showQrModal est deprecated : la modale officielle fait maintenant partie d'AppKit, l'ex-Web3Modal[Reown], que le TD interdit. La doc décrit l'autre voie, « Use without AppKit » : écouter l'événement display_uri et afficher l'URI soi-même. C'est ce que fait ton code avec la librairie qrcode, qui ne fait que dessiner.

wc.on("display_uri", (uri) => toDataURL(uri).then(setWcQr)); // 1. URI → image QR
wc.on("accountsChanged", …); wc.on("chainChanged", …);        // 2. mêmes événements que 0001
await wc.connect();                                          // 3. attend que le téléphone accepte

4. À toi

  1. Sur localhost:3000, dans une fenêtre privée (sans Rabby), clique WalletConnect (QR code).
  2. Scanne le QR avec un wallet mobile compatible WalletConnect (Rabby mobile, MetaMask mobile…). Accepte la connexion.
  3. Vérifie que ton adresse s'affiche. Si le téléphone n'est pas sur Sepolia, clique Switch to Sepolia : la demande arrive sur le téléphone, via le relay.
  4. Dans ton wallet mobile, déconnecte le site. Que devient la page ? Retrouve dans useWallet.ts la ligne qui explique ce comportement.

5. Rappel, de mémoire

Que contient le QR code affiché par ta page ?
L'URI de pairing reçue via display_uri. Aucune clé ne quitte le téléphone : il signe et renvoie seulement le résultat.
Pourquoi submitExercise marche sans modification avec WalletConnect ?
Même interface (request, on). getWalletClient() enveloppe simplement le provider actif avec custom(provider).
Écris le nom de l'événement qui donne l'URI à transformer en QR code.
display_uri.
