Routes et redirection avec l'App Router

Un dossier = une URL. Et c'est toi qui écris la redirection.

Objectif : tu crées toi-même la page d'erreur et la redirection quand le wallet n'est pas sur Sepolia. Ça couvre les deux points de « Chain Detection ».

0. Échauffement

Avec WalletConnect, pourquoi une méthode peut-elle être refusée avant même d'atteindre le téléphone ?
Le SDK vérifie les namespaces de la session (méthodes et chaînes acceptées par le wallet) et rejette localement le reste. C'est l'erreur « Missing or invalid. request() method » que tu as eue. Voir 0002.

1. Un dossier = une URL

Dans l'App Router, une page est un fichier page.tsx dans app/ qui exporte un composant par défaut[Next]. Le chemin des dossiers donne l'URL :

fichierURL
src/app/page.tsx/
src/app/chain-info/page.tsx/chain-info (je viens de la créer)
src/app/wrong-network/page.tsx/wrong-network (à toi)

2. Pourquoi "use client" en haut de /chain-info

Par défaut, un composant de l'App Router est un Server Component : il est rendu sur le serveur, sans state ni accès au navigateur. Ajouter "use client" en première ligne en fait un Client Component, nécessaire dès qu'on utilise du state, des effets, des événements ou des API du navigateur[Next]. /chain-info utilise useState, useEffect et le wallet (window.ethereum), d'où la directive.

Ouvre erc721-ux/src/app/chain-info/page.tsx et repère :

  • useWallet(), qui donne chainId et account (leçon 0001) ;
  • publicClient.watchBlockNumber(…) : viem interroge le RPC et appelle setBlockNumber à chaque nouveau bloc. La fonction renvoie unwatch, et retourner unwatch depuis le useEffect arrête le suivi quand tu quittes la page.

3. Deux façons de rediriger côté client

outiloù l'appeler
redirect("/x") de next/navigationpendant le rendu d'un Client Component, mais pas dans un gestionnaire d'événement[Next]
useRouter().replace("/x")dans un gestionnaire d'événement ou un effet. replace n'ajoute pas d'entrée dans l'historique, contrairement à push[Next]

Ici, chainId fait partie du state. Quand Rabby change de réseau, chainChanged met le state à jour, React refait le rendu, et ce nouveau rendu peut appeler redirect. Les deux outils marchent. redirect pendant le rendu est le plus court.

4. À toi de coder

  1. Crée la page d'erreur. Fichier erc721-ux/src/app/wrong-network/page.tsx : un message « Wrong network, please switch to Sepolia » et un bouton qui appelle switchToSepolia de useWallet(). Pense à la première ligne : en as-tu besoin ici ?
  2. Ajoute la redirection dans chain-info/page.tsx : si le wallet est sur un autre réseau que Sepolia, envoie vers /wrong-network.
    Piège : au premier rendu, chainId vaut undefined (pas encore lu, ou pas de wallet). Il ne faut pas rediriger dans ce cas.
    Indice : l'ID de Sepolia est déjà dans chain.id (@/lib/config).
  3. Bonus : sur /wrong-network, une fois de retour sur Sepolia, renvoie l'utilisateur vers /chain-info.
  4. Teste : ouvre /chain-info avec Rabby sur Sepolia, puis passe Rabby sur mainnet. Tu dois atterrir sur /wrong-network. Clique le bouton : tu dois revenir sur Sepolia.
Voir une solution (seulement après avoir essayé) 
// chain-info/page.tsx, dans le composant, après useWallet()
import { redirect } from "next/navigation";
import { chain } from "@/lib/config";

if (chainId !== undefined && chainId !== chain.id) redirect("/wrong-network");
// wrong-network/page.tsx
"use client"; // useWallet = state + window.ethereum
import { redirect } from "next/navigation";
import { useWallet } from "@/hooks/useWallet";

export default function WrongNetworkPage() {
  const { isCorrectChain, switchToSepolia, error } = useWallet();
  if (isCorrectChain) redirect("/chain-info"); // bonus
  return (
    <main className="mx-auto flex max-w-xl flex-col gap-4 p-8">
      <h1 className="text-2xl font-semibold">Wrong network</h1>
      <p>This dApp only works on Sepolia.</p>
      <button onClick={switchToSepolia} className="rounded-lg border px-4 py-2">Switch to Sepolia</button>
      {error && <p className="text-red-600">{error}</p>}
    </main>
  );
}

5. Rappel, de mémoire

Le TD demande la page /fakeBayc. Quel fichier dois-tu créer ?
src/app/fakeBayc/page.tsx. Le nom du dossier donne l'URL, et page.tsx la rend accessible.
Quand un composant a-t-il besoin de "use client" ?
State (useState), effets (useEffect), événements, API du navigateur (window.ethereum). Afficher du contenu ou importer viem ne suffit pas à l'exiger.
Pourquoi tester chainId !== undefined avant de rediriger ?
Avant que eth_chainId réponde, ou sans wallet, chainId vaut undefined. Sans ce test, tout le monde serait redirigé dès l'ouverture de la page.
