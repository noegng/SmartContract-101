TD ERC721 UX 101 · Leçon 0004 · ~25 min

Lire et écrire un contrat avec viem

readContract pour lire, simuler → envoyer → attendre pour écrire.

Objectif : tu écris toi-même la page /fakeBayc, tu claim un FakeBAYC depuis ton site, puis tu valides l'exercice 1 auprès de l'Evaluator. Ça couvre 2 points manuels et 2 automatiques.

0. Échauffement

Dans un composant, où placer un redirect() conditionnel ?
Tous les hooks d'abord, les sorties ensuite (Rules of Hooks). C'est la correction de la leçon 0003.

1. Ce que tu sais déjà du contrat

Tu connais le côté Solidity, c'est ton TD ERC721-101. FakeBAYC est un ERC721Enumerable avec une fonction gratuite :

function claimAToken() public { _safeMint(msg.sender, tokenCounter); tokenCounter++; }

Ce qui est nouveau, c'est de l'appeler depuis le navigateur. J'ai déjà ajouté FAKE_BAYC_ADDRESS dans src/lib/config.ts et fakeBaycAbi (name, totalSupply, balanceOf, claimAToken) dans src/lib/abis.ts.

2. Lire : readContract

Une fonction view ne coûte pas de gas et ne passe pas par le wallet : c'est le publicClient (ton RPC Alchemy) qui fait l'appel[viem].

const supply = await publicClient.readContract({
  address: FAKE_BAYC_ADDRESS,
  abi: fakeBaycAbi,
  functionName: "totalSupply",
}); // 42n (un bigint, car uint256 ne tient pas dans un number)

Grâce au as const de l'ABI, TypeScript connaît le type de retour : string pour name, bigint pour totalSupply. Pour afficher un bigint dans du JSX, appelle .toString().

Modèle dans ton projet : src/components/Points.tsx (un useEffect qui lit puis appelle setState).

3. Écrire : trois étapes

writeContract envoie la transaction sans vérifier qu'elle va réussir. viem recommande de simuler d'abord[viem].

// 1. simuler : exécute l'appel « à blanc » via le RPC ; un revert arrive ici, avec sa raison
const { request } = await publicClient.simulateContract({
  account, address: FAKE_BAYC_ADDRESS, abi: fakeBaycAbi, functionName: "claimAToken",
});
// 2. envoyer : le wallet ouvre sa fenêtre de signature ; renvoie le hash de la tx
const hash = await getWalletClient()!.writeContract(request);
// 3. attendre : la tx est minée (ou revert)
const receipt = await publicClient.waitForTransactionReceipt({ hash });

Modèle dans ton projet : src/components/SubmitExercise.tsx fait exactement ces trois étapes, avec un état « pending » et un lien Etherscan.

Pourquoi passer account à la simulation ? Le contrat utilise msg.sender. Sans account, la simulation tournerait sans expéditeur, et un contrat qui vérifie l'appelant (comme l'Evaluator) ferait revert.

"use client";
import { useEffect, useState } from "react";
import { publicClient } from "@/lib/clients";
import { fakeBaycAbi } from "@/lib/abis";
import { FAKE_BAYC_ADDRESS } from "@/lib/config";

export default function FakeBaycPage() {
  const [name, setName] = useState<string>();
  const [supply, setSupply] = useState<bigint>();

  useEffect(() => {
    const contract = { address: FAKE_BAYC_ADDRESS, abi: fakeBaycAbi } as const;
    publicClient.readContract({ ...contract, functionName: "name" }).then(setName);
    publicClient.readContract({ ...contract, functionName: "totalSupply" }).then(setSupply);
  }, []);

  return (
    <main className="mx-auto flex max-w-xl flex-col gap-4 p-8">
      <h1 className="text-2xl font-semibold">{name ?? "…"}</h1>
      <p>Total minted: {supply?.toString() ?? "…"}</p>
    </main>
  );
}

5. Rappel, de mémoire

Pourquoi name() ne déclenche-t-il aucune fenêtre dans Rabby ?
Une fonction view ne change pas l'état : le publicClient l'exécute via le RPC (eth_call), sans signature et sans gas.
À quoi sert simulateContract avant writeContract ?
writeContract ne valide rien. La simulation exécute l'appel à blanc : si ça revert (par exemple « Evaluator: no FakeBAYC held »), l'utilisateur le sait avant de signer et de payer.
Quel type JavaScript viem renvoie-t-il pour un uint256 ?
bigint (ex. 42n). Un number perd en précision au-delà de 253, alors qu'un uint256 monte à 2256.

Source principale à lire (10 min) : viem : writeContract, puis readContract.
Une erreur TypeScript sur functionName ou args ? C'est souvent l'ABI. Colle-moi le message, on la lira ensemble.
