Route dynamique et métadonnées NFT

/fakeBayc/42 : de l'URL au contrat, du contrat à IPFS, d'IPFS à l'écran.

Objectif : tu écris seul la page /fakeBayc/[tokenId], qui affiche l'image et les attributs d'un token, avec un état d'erreur propre si le token n'existe pas. Ça couvre 2 points manuels.

0. Échauffement

TypeScript dit : « Type '{ functionName }' is missing the following properties: label, account, address, abi ». Que faire ?
L'erreur donne la réponse : les props manquantes sont listées. Lire le message jusqu'au bout avant de chercher ailleurs, c'est le réflexe à prendre (leçon 0004).

1. Un dossier entre crochets = un paramètre

Un dossier nommé [tokenId] capture la partie de l'URL qui est à sa place[Next] :

fichierURLparams
app/fakeBayc/[tokenId]/page.tsx/fakeBayc/0{ tokenId: "0" }
(même fichier)/fakeBayc/abc{ tokenId: "abc" }, une chaîne qu'il faudra valider

Dans Next 16, params est une Promise. Dans un Client Component, on la lit avec use() de React[Next] :

"use client";
import { use } from "react";

export default function TokenPage({ params }: { params: Promise<{ tokenId: string }> }) {
  const { tokenId } = use(params);   // "0", "42", "abc"…

Le piège de Next 16 : loading.tsx obligatoire ici

Ton next.config.ts active cacheComponents: true, l'option par défaut des nouveaux projets Next 16[Next]. Avec ce mode, Next pré-rend chaque page à l'avance. Mais un paramètre d'URL inconnu à l'avance, comme [tokenId], est une donnée « de requête » : la lire hors d'une frontière <Suspense> déclenche l'erreur blocking-prerender-dynamic. Je l'ai obtenue en testant la solution de cette leçon.

La correction la plus simple : un fichier loading.tsx dans le même dossier. Next enveloppe alors automatiquement la page dans un <Suspense>, avec ce composant comme écran d'attente[Next].

// src/app/fakeBayc/[tokenId]/loading.tsx
export default function Loading() {
  return <main className="p-8">Loading…</main>;
}

2. Du contrat à l'image : trois sauts

J'ai vérifié chaque saut sur le vrai contrat, avec le token 0 :

  1. Contrat : tokenURI(0n) renvoie
    https://gateway.pinata.cloud/ipfs/QmeSji…/0. C'est une URL HTTP, que le navigateur a le droit de lire (en-tête access-control-allow-origin: *).
  2. JSON : un fetch de cette URL donne : 
    { "image": "ipfs://QmRRPWG96cmgTn2qSzjwr2qvfNEuhunv6FNeMFGa9bx6mQ",
  "attributes": [ { "trait_type": "Fur", "value": "Robot" }, … ] }
    Il n'y a ni name ni description, comme le prévient le README du TD.
  3. Image : le navigateur ne sait pas ouvrir ipfs://…. Il faut passer par une passerelle (gateway) HTTP :
    ipfs://Qm… → https://gateway.pinata.cloud/ipfs/Qm…
    J'ai testé : Pinata répond 200 (image PNG), mais met ~5 s à l'afficher. ipfs.io répond 429 (trop de requêtes), donc pas fiable aujourd'hui.

3. Le token n'existe pas

Pour tokenURI(999999n), le contrat revert avec « ERC721: invalid token ID ». C'est le message d'OpenZeppelin v4, que j'ai lu sur le contrat réel. viem le transmet comme une erreur rejetée, et tu l'attrapes dans un .catch.

Il y a deux cas d'erreur différents à afficher proprement :

  • /fakeBayc/abc : BigInt("abc") lance une exception avant tout appel au contrat ;
  • /fakeBayc/999999 : le contrat revert.

4. À toi de coder

  1. Crée src/app/fakeBayc/[tokenId]/loading.tsx (ci-dessus), puis page.tsx, et affiche le tokenId lu avec use(params). Teste /fakeBayc/0. Pour voir le piège, supprime un instant loading.tsx et lis l'erreur dans la console.
  2. Dans un useEffect : readContract(tokenURI), puis fetch(uri), puis res.json(). Garde le JSON dans un state. Il faut ajouter tokenURI à fakeBaycAbi : à toi de trouver son entrée dans l'ABI (indice : regarde balanceOf, qui prend aussi un argument).
  3. Affiche l'image (convertis ipfs:// en URL Pinata) et la liste des attributs trait_type: value.
  4. Ajoute un state error : en cas d'échec (tokenId invalide ou revert), affiche « Token #… does not exist » au lieu d'un écran vide ou d'un chargement infini.

Note : pour une image externe, Next propose <Image>, mais il faut alors autoriser le domaine dans next.config.ts. Un simple <img> suffit ici. Le lint signalera un warning (no-img-element), et c'est normal.

Voir une solution (seulement après avoir essayé) 
// abis.ts, dans fakeBaycAbi
{ type: "function", name: "tokenURI", stateMutability: "view",
  inputs: [{ name: "tokenId", type: "uint256" }], outputs: [{ name: "", type: "string" }] },

Plus loading.tsx (section 1), puis :

"use client";
import { use, useEffect, useState } from "react";
import { publicClient } from "@/lib/clients";
import { fakeBaycAbi } from "@/lib/abis";
import { FAKE_BAYC_ADDRESS } from "@/lib/config";

type Metadata = { image: string; attributes: { trait_type: string; value: string }[] };

const toHttp = (uri: string) => uri.replace("ipfs://", "https://gateway.pinata.cloud/ipfs/");

export default function TokenPage({ params }: { params: Promise<{ tokenId: string }> }) {
  const { tokenId } = use(params);
  const [meta, setMeta] = useState<Metadata>();
  const [error, setError] = useState(false);

  useEffect(() => {
    Promise.resolve()
      .then(() => publicClient.readContract({
        address: FAKE_BAYC_ADDRESS, abi: fakeBaycAbi, functionName: "tokenURI",
        args: [BigInt(tokenId)],          // lance une exception si tokenId = "abc"
      }))
      .then((uri) => fetch(uri))
      .then((res) => res.json())
      .then(setMeta)
      .catch(() => setError(true));
  }, [tokenId]);

  if (error) return <main className="p-8">Token #{tokenId} does not exist.</main>;
  if (!meta) return <main className="p-8">Loading…</main>;

  return (
    <main className="mx-auto flex max-w-xl flex-col gap-4 p-8">
      <h1 className="text-2xl font-semibold">FakeBAYC #{tokenId}</h1>
      <img src={toHttp(meta.image)} alt={`FakeBAYC #${tokenId}`} width={400} height={400} />
      <ul>
        {meta.attributes.map((a) => (
          <li key={a.trait_type}>{a.trait_type}: {a.value}</li>
        ))}
      </ul>
    </main>
  );
}

Pourquoi Promise.resolve().then(…) ? Pour que l'exception de BigInt("abc") tombe dans le même .catch que le revert, au lieu de faire planter le composant.

5. Rappel, de mémoire

Le TD demande /fakeBayc/gallery/[address]. Quel fichier crées-tu ?
src/app/fakeBayc/gallery/[address]/page.tsx. gallery est un segment fixe, [address] un segment dynamique. C'est la leçon suivante.
Pourquoi ne peut-on pas mettre ipfs://Qm… directement dans <img src> ?
Les navigateurs ne gèrent que http(s)://. Une passerelle HTTP (Pinata ici) va chercher le contenu sur IPFS et le sert en HTTPS.
Que vaut tokenId pour l'URL /fakeBayc/7 ?
Un paramètre d'URL est toujours une chaîne. C'est à toi de la convertir (BigInt(tokenId)) et de gérer le cas où la conversion échoue.
